# 系统评估 (System Evaluation)

> 来源：https://docs.openvins.com/evaluation.html + eval-metrics + eval-error + eval-timing

---

## 一、评估目标

确保与自身及其他方法的**公平比较**。评估指标分为：
- **准确性**：估计值离真值多远
- **一致性**：估计的不确定性是否反映真实误差
- **实时性**：计算是否满足实时约束

---

## 二、评估指标（详细定义与推导）

### 1. 绝对轨迹误差 (ATE)

将估计轨迹与真值轨迹**对齐**后（因为全局坐标系不同），计算误差。

**对齐**：找到最优刚体变换 $(\mathbf{R}_{align}, \mathbf{p}_{align})$ 使：

$$\min_{\mathbf{R},\mathbf{p}} \sum_{i=1}^{N} \|\mathbf{p}_{est,i} - (\mathbf{R} \mathbf{p}_{gt,i} + \mathbf{p})\|^2$$

求解：用**Umeyama方法**（带/不带尺度）

$$\text{ATE}_{pos} = \sqrt{\frac{1}{N} \sum_{i=1}^{N} \|\mathbf{p}_{est,i}^{aligned} - \mathbf{p}_{gt,i}\|^2}$$

$$\text{ATE}_{ori} = \sqrt{\frac{1}{N} \sum_{i=1}^{N} \|\log(\mathbf{R}_{est,i}^{aligned} \mathbf{R}_{gt,i}^\top)\|^2}$$

**对齐模式**：
- `posyaw`：仅对齐平移和绕重力的旋转（适合VIO，因为roll/pitch可观）
- `se3`：完整SE(3)对齐（6DoF）
- `sim3`：带缩放的SE(3)对齐（单目无尺度时使用）

### 2. 相对位姿误差 (RPE) — 推荐优先使用

将轨迹分段，每段长度 $\Delta$，计算段内相对误差：

$$\mathbf{E}_i = (\mathbf{T}_{est,i}^{-1} \mathbf{T}_{est,i+\Delta})^{-1} (\mathbf{T}_{gt,i}^{-1} \mathbf{T}_{gt,i+\Delta})$$

$$\text{RPE}_{pos}(\Delta) = \frac{1}{M} \sum_{i=1}^{M} \|\text{trans}(\mathbf{E}_i)\|$$

$$\text{RPE}_{ori}(\Delta) = \frac{1}{M} \sum_{i=1}^{M} \|\log(\text{rot}(\mathbf{E}_i))\|$$

**为什么RPE更公平？**

- ATE对单次误差跳跃（如一帧跟踪丢失后重定位）**非常敏感**
- RPE将轨迹采样为多个小段 → 减少单次跳跃的影响
- RPE按$\Delta$分段可看出**漂移如何随距离增长**

例如：RPE(8m, 16m, 24m, 32m, 40m) → 漂移曲线

### 3. 均方根误差 (RMSE) — 时间维度

在每个时间步计算多次运行的RMSE：

$$\text{RMSE}_{pos}(t_k) = \sqrt{\frac{1}{R} \sum_{r=1}^{R} \|\mathbf{p}_{est,r}(t_k) - \mathbf{p}_{gt}(t_k)\|^2}$$

$R$ = 同一数据集上的运行次数（需蒙特卡洛仿真）。

**价值**：可看出**哪些时间段**性能差（如快速转弯、动态场景段）。

### 4. 归一化估计误差平方 (NEES) — 一致性

**定义**：
$$\eta_k = \tilde{\mathbf{x}}_k^\top \mathbf{P}_k^{-1} \tilde{\mathbf{x}}_k$$

其中 $\tilde{\mathbf{x}}_k = \mathbf{x}_{est,k} \ominus \mathbf{x}_{gt,k}$，$\mathbf{P}_k$ 是估计器报告的协方差。

**多运行平均**：
$$\overline{\text{NEES}}_k = \frac{1}{R} \sum_{r=1}^{R} \eta_k^{(r)}$$

**一致性判断**：

$\mathbb{E}[\eta_k] = \dim(\tilde{\mathbf{x}})$，即NEES应等于误差状态维度。

- 位置NEES：期望值 = 3 → $\overline{\text{NEES}} \approx 3$ = 一致
- $\overline{\text{NEES}} \gg 3$：**过度自信**（P太小）→ 滤波器不一致
- $\overline{\text{NEES}} \ll 3$：**过度保守**（P太大）→ 浪费信息

**NEES的卡方解释**：

$\eta_k \sim \chi^2(d)$（在一致性假设下），因此可以通过卡方检验判断：
- 如果 $R \cdot \overline{\text{NEES}}_k \sim \chi^2(R \cdot d)$，则一致
- 双边界卡方检验可拒绝一致性假设

### 5. 单次运行一致性可视化

对单次运行，绘制每个状态分量：

$$\text{Error}_k = \tilde{x}_k, \quad \text{Bound}_k = 3\sigma_k = 3\sqrt{P_{kk}}$$

如果 $\text{Error}_k \leq 3\sigma_k$ 约99.7%的时间（高斯假设下）→ 一致。

**典型模式**：
- 误差持续超出 $3\sigma$ → 过度自信（最常见的不一致表现）
- 误差远在 $3\sigma$ 内 → 过度保守

## 四、时序分析

### 关键指标

| 指标 | 含义 |
|------|------|
| mean | 平均耗时（是否符合实时约束） |
| std | 耗时波动（稳定性） |
| 99th percentile | **最坏情况延迟**（对实时系统最重要） |
| max | 绝对最大延迟 |

### 典型组件耗时

```
tracking:        mean=0.0037s  99th=0.0063s
propagation:     mean=0.0004s  99th=0.0006s
msckf update:    mean=0.0032s  99th=0.0083s
slam update:     mean=0.0034s  99th=0.0063s
slam delayed:    mean=0.0012s  99th=0.0052s
marginalization: mean=0.0009s  99th=0.0015s
─────────────────────────────────────────
total:           mean=0.0128s  99th=0.0208s
```

**实时性分析**：total mean 12.8ms < 1/30Hz = 33ms → 满足30Hz实时

## 五、评估最佳实践

### RPE vs ATE

| | ATE | RPE |
|---|---|---|
| 含义 | 全局绝对精度 | 局部漂移率 |
| 对跳跃敏感度 | 高 | 低 |
| 提供漂移vs距离 | 否 | 是 |
| 推荐程度 | 补充 | **主要** |

### 准确性 vs 一致性

- ATE/RMSE = 准确性（估计离真值多远）
- NEES = 一致性（滤波器声称的不确定性是否正确）

这两个是**正交**的评估维度：
- 系统可能准确但不一致（P太小/太大）
- 系统可能一致但不准确（P正确但估计偏离真值）
- **理想系统**：准确 AND 一致

### 统计有效性

- 仿真：多次运行（$R \geq 10$），固定状态种子，变化噪声种子
- 真实数据：多数据集、多配置，报告均值和标准差

## 面试要点

1. **RPE优先于ATE**：对误差跳跃不敏感，提供漂移vs距离信息
2. **NEES告诉你一致性**：NEES≈d（状态维度）= 一致，NEES>>d = 过度自信
3. **3σ边界**：正常情况下99.7%的误差应在±3σ内
4. **4DoF对齐**：VIO的yaw和位置不可观 → `posyaw`对齐比`se3`更合理
5. **99分位 > 均值**：实时系统关注最坏情况延迟
6. **蒙特卡洛的必要性**：消除单次噪声的偶然性，获得统计有效评估
