ORB-SLAM2是2017年发表于T-RO的视觉SLAM开源方案，支持单目、双目和RGB-D三种相机，核心贡献是把**ORB特征**、**多线程架构**和**g2o图优化**整合成一个完整、鲁棒、实时的SLAM系统。

Tracking线程是**每帧都运行**的，负责实时估计当前帧的相机位姿。它提取ORB特征后，先假设相机做匀速运动，将上一帧的地图点投影到当前帧做匹配。如果匹配不够，就用更‘暴力’的**词袋模型**做宽基线匹配。跟踪成功后，根据规则判断是否需要插入关键帧；如果跟踪失败，就用词袋做**重定位**，相当于从丢失状态中恢复。

Local Mapping 这个线程**只处理关键帧**，频率比Tracking低。它把新关键帧插入共视图后，用三角化生成新的地图点，然后做**局部BA优化**——只优化当前关键帧和它相邻的一圈关键帧，以及它们看到的地图点，这样既保证了精度又保证了实时性。优化完后，它会剔除冗余的关键帧（建图没贡献的）和冗余的地图点（观测次数少的），控制BA的规模。

回环检测线程用DBoW2词袋模型来检测当前关键帧和之前的关键帧是否有相似性。为了防误检，ORB-SLAM2会做**时间连续性检查**和**几何一致性校验**——连续3个候选帧都匹配上，才算确认回环。确认后先做**位姿图优化**来矫正累积漂移，再触发第四个线程跑**全局BA**，一次性优化所有关键帧和地图点。

#### ORB特征有什么优点？为什么要用它？

答：ORB是**Oriented FAST + Rotated BRIEF**的组合，本质是一个**二进制特征描述子**。它的优点有三个：

- **速度快**：FAST角点提取和BRIEF二进制描述子生成都很快，适合实时SLAM
    
- **旋转不变性**：通过灰度质心法计算特征点的主方向，让BRIEF描述子带上旋转信息（rBRIEF）
    
- **尺度不变性**：通过构建**8层图像金字塔**，在不同尺度上分别提取特征，确保远近都能匹配到
    

相比于SIFT和SURF（虽然更鲁棒但太慢），ORB在**精度和速度之间取得了很好的平衡**，所以ORB-SLAM2全程使用ORB特征——**Tracking用它做匹配，Local Mapping用它三角化，Loop Closing用它做词袋检索**，三处统一，工程上非常干净。

#### ORB特征是怎么做到均匀分布的？

答：ORB-SLAM2用了三招来保证特征点在整个图像上均匀分布，避免全部扎堆在纹理丰富区域：

1. **图像金字塔**：在8层尺度上分别提特征，每层都提，保证远近都有
    
2. **网格划分**：每层图像划分成若干网格，每个网格独立提取FAST角点，保证空间均匀
    
3. **四叉树筛选（核心）**：检测完角点后，把整张图片作为一个根节点，递归四叉树划分，直到叶子节点数量达到目标特征数，每个叶子节点只保留**响应值最大**的那个特征点
    

这个四叉树方法能保证特征点不扎堆，在低纹理区域也能保留一些特征，对追踪鲁棒性至关重要。

#### 什么时候用基础矩阵F，什么时候用单应矩阵H？

答：这是一个经典的面试题，考察你对多视图几何的理解。

- **基础矩阵F**描述了两个视图之间的**极线几何约束**，适用于一般场景，要求场景不是纯平面，且相机有平移
    
- **单应矩阵H**描述了两个视图之间的**平面投影变换**，适用于**特征点都在同一个平面上**的场景，或者**相机发生纯旋转**（没有平移）时
    

ORB-SLAM2的做法是：**同时计算F和H，然后算它们的重投影误差，哪个误差小就用哪个**。这样可以自适应地处理“平面场景”和“非平面场景”，鲁棒性更好。如果选F，就用**8点法+RANSAC**求本质矩阵E再分解；如果选H，就直接从单应矩阵分解R和t。

#### ORB-SLAM2的BA优化分别在什么地方用了？

答：ORB-SLAM2用了三个层次的BA优化，由粗到精：

|BA类型|优化变量|固定变量|触发时机|复杂度|
|---|---|---|---|---|
|**纯运动BA**|当前帧的位姿|所有地图点|每帧Tracking|最小，实时|
|**局部BA**|当前关键帧 + 邻域关键帧 + 局部地图点|其他关键帧|每插入一个关键帧|中等，不影响实时性|
|**全局BA**|所有关键帧 + 所有地图点|无|回环确认后（单独线程）|最大，跑几秒|

局部BA的优化窗口是**当前关键帧 + 共视图中相邻的一圈关键帧**，以及它们观测到的地图点，这样就保证了计算量是局部可控的。

全局BA因为计算量大，在单独的线程里异步执行，不影响Tracking的实时性。

#### 关键帧是怎么筛选的？标准是什么？

答：ORB-SLAM2的关键帧策略是**“宽松插入，严格剔除”**，目的是既保证地图有足够的帧来建图，又不让关键帧太多导致BA计算量爆炸。

**插入条件（宽松）**：满足下面任一条件就插入关键帧：

- 距离上次关键帧已经超过一定帧数（单目是20帧）
    
- 当前帧追踪到的地图点数量低于阈值（比如少于100个），说明场景变化大，需要新帧来建图
    
- 当前帧和最近关键帧的共视点比例低于90%（说明看到了新区域）
    

**剔除条件（严格）**：在Local Mapping线程里，检查关键帧的地图点被其他关键帧观测到的比例，如果90%以上的地图点已经被其他关键帧看到了，说明这个关键帧是冗余的，直接剔除，保证局部BA的规模可控。

#### 回环检测是怎么做的？怎么防误检？

答：ORB-SLAM2的回环检测分三步走：

> **第一步：词袋检索候选帧**
> 
> - 当前关键帧的ORB特征转成词袋向量（DBoW2）
>     
> - 在关键帧数据库中查询相似的候选关键帧
>     
> - 排除与当前帧有共视关系的候选（排除刚走过的地方）
>     
> 
> **第二步：时间连续性检查**
> 
> - 候选关键帧必须**连续3帧**都被检索到，才能进入下一步
>     
> - 这样可以过滤掉偶发的相似性（比如两张白墙意外相似）
>     
> 
> **第三步：几何一致性校验**
> 
> - 用候选帧和当前帧做特征匹配
>     
> - 计算Sim3变换（因为单目存在尺度漂移，需要用相似变换而不是刚体变换）
>     
> - 如果Sim3重投影误差足够小，才确认回环

只有三个关卡全过了，才真正触发回环矫正，非常保守，**误检率极低**。

回环确认后，先用**位姿图优化**（只优化关键帧位姿，不优化地图点），矫正累积漂移，然后触发**全局BA**（所有关键帧+所有地图点）把精度修到最高。因为全局BA计算量大，在单独的线程里异步执行，不阻塞前端。

#### 你觉得ORB-SLAM2有什么不足？怎么改进？

> 答：几个主要不足和对应的改进思路：

| 不足                       | 改进方案                                    |
| ------------------------ | --------------------------------------- |
| **没有IMU融合**，快速运动/纯旋转容易跟丢 | 接入IMU做紧耦合（ORB-SLAM3的思路），用IMU预积分辅助预测和初始化 |
| **低纹理环境**（白墙、走廊）特征少，容易跟丢 | 引入线特征或面特征做补充，或者用深度学习提密集特征点              |
| **动态环境**（行人、车辆）误匹配多      | 前端加语义分割网络（如YOLO），动态物体上的特征点直接剔除          |
| **稀疏地图**无法用于导航避障         | 结合RGB-D或双目生成半稠密/稠密地图，或者接入OctoMap        |
| **单目模式下**存在尺度漂移          | 双目版本能解决，或者接IMU（ORB-SLAM3的方案）            |

#### ORB-SLAM2单目初始化是怎么做的？

> 答：单目初始化是单目SLAM最关键的步骤，ORB-SLAM2的做法是**并行计算F和H，选误差小的那个**，具体流程：

> 1. 从第一帧和第二帧中提取ORB特征，做匹配
>     
> 2. 同时用RANSAC计算**基础矩阵F**和**单应矩阵H**
>     
> 3. 分别从F和H分解出R、t和3D点，算重投影误差
>     
> 4. **哪个误差小就采用哪个模型**——一般场景F好，平面场景H好
>     
> 5. 初始化成功后，把这两帧作为初始关键帧插入地图
>     
> 6. 如果初始化失败（匹配不够），就继续等下一帧重新试
>     
> 
> 这个“并行计算二选一”的策略，让ORB-SLAM2在平面场景（如桌面）和一般场景（如室外）都能成功初始化，鲁棒性非常好。
